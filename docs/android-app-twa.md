# بسته‌بندی به‌عنوان اپلیکیشن اندروید واقعی (TWA) — رفع محدودیت نصب مرورگری

## چرا این لازم شد

نصب از طریق مرورگر (Add to Home Screen / نصب PWA) وابسته به «امتیاز
تعامل» (Engagement Score) خودِ Chrome است — کاربر تازه باید چند بار در
چند روز مختلف از سایت بازدید کند تا Chrome نصب واقعی پیشنهاد بدهد
(جزئیات کامل در [`docs/pwa.md`](pwa.md)). برای یک اپ سازمانی که پرسنل
تازه‌وارد باید فوراً نصبش کنند، این قابل‌قبول نیست.

**راه‌حل**: بسته‌بندی همین PWA (بدون بازنویسی هیچ کدی) به‌عنوان یک
اپلیکیشن اندروید واقعی (APK) با فناوری رسمی گوگل **TWA (Trusted Web
Activity)**. این یک نصب APK واقعی است — کاملاً مستقل از هر محدودیت
مرورگری، همان لحظه اول قابل‌نصب و تمام‌صفحه.

⚠️ این بخش (تولید APK) نیاز به Android SDK/JDK دارد که باید **روی سیستم
خودتان** اجرا شود، نه روی سرور — Bubblewrap (ابزار رسمی گوگل) این کار را
تقریباً کاملاً خودکار انجام می‌دهد.

## پیش‌نیاز (یک‌بار، روی سیستم خودتان)

- [Node.js](https://nodejs.org) نسخه ۱۸ به بالا
- یک JDK (نسخه ۱۷ توصیه می‌شود — Bubblewrap امروزه خودش هم می‌تواند دانلودش کند)
- Android SDK Command-line Tools (Bubblewrap هم می‌تواند خودش دانلود کند)

## مرحله ۱ — نصب Bubblewrap

```bash
npm install -g @bubblewrap/cli
```

## مرحله ۲ — ساخت پروژه از روی Manifest واقعی

```bash
mkdir faipco-android && cd faipco-android
bubblewrap init --manifest https://portal.faipco.ir/manifest.json
```

یک ویزارد تعاملی شروع می‌شود و بیشتر مقادیر را از `manifest.json` واقعی
شما می‌خواند (نام، آیکون‌ها، رنگ‌ها). چند نکته مهم موقع پاسخ‌دادن:

- **Package name**: پیشنهاد پیش‌فرض معمولاً چیزی شبیه `ir.faipco.portal`
  است — همین را قبول کنید، چون دقیقاً همین مقدار از قبل در
  `frontend/public/.well-known/assetlinks.json` نوشته شده. اگر اسم دیگری
  انتخاب کردید، حتماً آن فایل را هم به همان مقدار به‌روز کنید.
- **Signing key**: یک Keystore جدید می‌سازد و رمز عبورش را می‌پرسد.
  ⚠️ **این فایل و رمزش را در جای امنی نگه دارید** (مثلاً یک Password
  Manager) — هر آپدیت آینده اپلیکیشن (نه محتوای وب، بلکه خودِ بسته APK)
  باید دقیقاً با همین کلید امضا شود؛ گم‌شدنش یعنی نمی‌توانید نسخه جدید
  اپلیکیشن را جایگزین قبلی کنید.

## مرحله ۳ — Build

```bash
bubblewrap build
```

خروجی یک فایل `app-release-signed.apk` است.

## مرحله ۴ — تأیید مالکیت دامنه (Digital Asset Links)

بعد از Build، Bubblewrap یک SHA-256 Fingerprint چاپ می‌کند (یا با دستور
زیر دوباره می‌توانید ببینیدش):

```bash
keytool -list -v -keystore android.keystore -alias android
```

این مقدار را کپی کنید و در سرور، در فایل
`frontend/public/.well-known/assetlinks.json` جایگزین
`REPLACE_WITH_REAL_SHA256_FINGERPRINT_AFTER_RUNNING_BUBBLEWRAP` کنید،
سپس یک آپدیت معمولی (`sudo bash install.sh` یا از پنل) بزنید تا این فایل
روی سرور به‌روز شود.

برای تأیید اینکه درست تنظیم شده:

```bash
curl https://portal.faipco.ir/.well-known/assetlinks.json
```

باید همان JSON با Fingerprint واقعی برگردد (نه صفحه HTML).

## مرحله ۵ — نصب و تست

```bash
bubblewrap install
```

(یک گوشی اندروید با فعال‌بودن USB Debugging به کامپیوتر وصل باشد.) اگر
Asset Links درست تنظیم شده باشد، اپلیکیشن **بدون هیچ نوار آدرس مرورگری**
— کاملاً شبیه یک اپ بومی — باز می‌شود. اگر Asset Links درست نبود، به‌طور
خودکار به یک Chrome Custom Tab (با نوار آدرس) سقوط می‌کند — یعنی هنوز کار
می‌کند، فقط ظاهرش کامل نیست؛ نشانه‌ای برای بررسی دوباره مرحله ۴.

## توزیع بین پرسنل

چون این یک اپ کاملاً داخلی سازمانی است، نیازی به Google Play نیست:

- ساده‌ترین راه: فایل `app-release-signed.apk` را جایی روی خودِ پرتال یا
  یک فضای اشتراکی داخلی بگذارید و یک لینک دانلود مستقیم به پرسنل بدهید.
  (اندروید موقع نصب یک فایل APK از منبع نامعتبر، یک هشدار امنیتی استاندارد
  نشان می‌دهد — طبیعی است، کاربر باید «نصب از منبع ناشناس» را تأیید کند.)
- جایگزین رسمی‌تر: انتشار در Google Play (یک‌بار هزینه ۲۵ دلاری حساب
  Developer + فرآیند بررسی گوگل) — برای یک اپ کاملاً داخلی معمولاً لازم
  نیست.

## نکته مهم — آپدیت محتوا در برابر آپدیت خودِ اپلیکیشن

- **آپدیت محتوا/کد** (همان چیزی که با `install.sh` یا پنل «بررسی و اعمال
  آپدیت» انجام می‌دهید): خودکار و بدون نیاز به کاری دیگر روی همه گوشی‌هایی
  که این اپ را نصب کرده‌اند منعکس می‌شود — چون TWA فقط همان وب‌سایت زنده
  را نمایش می‌دهد.
- **آپدیت خودِ بسته APK** (مثلاً تغییر آیکون/نام اپ، یا آپدیت نسخه Chrome
  که TWA به آن وابسته است): فقط اگر خودِ فایل `twa-manifest.json` را عوض
  کرده باشید لازم است — با `bubblewrap update` و `bubblewrap build` دوباره
  (با همان Keystore قبلی) بسازید و فایل APK جدید را توزیع کنید.
