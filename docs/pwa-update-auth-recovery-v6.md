# اصلاح بازیابی نشست هنگام به‌روزرسانی PWA / اندروید — نسخه v6

مبنا: FAIPCO-Portal-PWA-Android-Update-Fix-v5.zip

## مشکل
در لحظهٔ تعویض Service Worker، صفحه مجدداً بارگذاری می‌شود. اگر نخستین درخواست `/auth/me` به‌دلیل وقفهٔ موقت Backend یا شبکه شکست بخورد، نسخهٔ قبلی `AuthContext` بارگذاری را تمام و `user` را خالی می‌کرد و `ProtectedRoute` به اشتباه کاربر را به `/login` می‌فرستاد. پس از Refresh دستی، توکن معتبر بود و نشست بازیابی می‌شد، اما مسیر قبلی از دست رفته بود.

## تغییرات
- خطای شبکه، Timeout یا پاسخ موقت 5xx هنگام `/auth/me` دیگر به معنی خروج از حساب نیست.
- مسیر جاری کاربر حفظ می‌شود؛ یک صفحهٔ بازیابی اتصال با دکمه تلاش دوباره نشان داده می‌شود.
- تلاش مجدد خودکار با تأخیر افزایشی ۲٫۵، ۵، ۱۰ و حداکثر ۲۰ ثانیه؛ بدون حلقهٔ سریع درخواست.
- هنگام تلاش مجدد، صفحه بین اسپینر تمام‌صفحه و پیام خطا جابه‌جا نمی‌شود.
- فقط نشست باطل‌شدهٔ واقعی (401 پس از منطق Refresh موجود) یا خروج اختیاری به صفحهٔ ورود هدایت می‌شود.
- فایل‌های SW نسخه v5 بدون تغییر مانده‌اند؛ این رفع باگ نیازی به APK جدید یا Migration ندارد.

## تست‌های واحد
`cd frontend && npm run test:unit` — ۲۰ تست موفق، از جمله ۴ تست جدید برای طبقه‌بندی خطا و رفتار محافظ مسیر.

## سناریوهای تست روی سرور تست
1. درون اپ اندروید وارد شوید و صفحه‌ای غیر از داشبورد (مثلاً اطلاعیه‌ها) را باز کنید.
2. نسخهٔ تازه‌ای منتشر کنید و بلافاصله روی «بارگذاری» بزنید؛ نباید صفحهٔ Login ظاهر شود.
3. در صورت قطع لحظه‌ای API، صفحه «در حال بازیابی اتصال پرتال» باید نمایش داده شود و پس از برقراری ارتباط، **همان مسیر قبلی** باز گردد.
4. خروج دستی کاربر همچنان باید صفحه Login را نمایش دهد.
5. نشست واقعاً نامعتبر باید مثل قبل به Login منتقل شود و توکن باطل حفظ نشود.
6. یک بار تست شبکه ضعیف/وقفهٔ کوتاه Backend انجام دهید؛ داده‌های فرم‌های ذخیره‌نشده در Reload ناشی از تأیید آپدیت ممکن است از بین بروند، بنابراین پیش از تأیید آپدیت فرم‌های باز را ذخیره کنید.

## محدودیت‌های اعتبارسنجی
Build تولیدی Frontend و اجرای تست واقعی در اندروید در محیط آماده‌سازی ممکن نشد (نصب وابستگی‌های npm به پایان نرسید). بنابراین بسته فقط برای سرور تست است.
