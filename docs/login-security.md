# امنیت ورود (Migration 092)

مسیر پنل: «کاربران و دسترسی ← امنیت ورود» (`/login-security`). مجوز: `system.login_security`، که روی کل سیستم اثر دارد و مدیر سیستم خودکار آن را دارد.

## تنظیمات
تنظیمات در `system_settings` با کلید `login_security` ذخیره می‌شوند. تا وقتی ذخیره نشده‌اند، پیش‌فرض‌ها همان رفتار قبلی سیستم‌اند.

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| هر چند تلاش یک پله | ۳ | قفل پلکانی هر شناسه (کد پرسنلی یا نام کاربری) |
| مدت پله‌ها | ۱، ۵ و ۶۰ دقیقه | بعد از آخرین پله، همان مدت آخر تکرار می‌شود |
| محدودیت IP | روشن؛ ۲۰ تلاش ناموفق در ۱۰ دقیقه ← ۱۵ دقیقه مسدودیت | تلاش ناموفق روی هر شناسه‌ای از یک IP شمرده می‌شود |
| IPهای معاف | — | IP یا CIDR. این IPها محدودیت IP و کپچای مبتنی بر IP ندارند، ولی قفل هر شناسه برایشان برقرار است |
| کپچا در ورود | بعد از ۲ تلاش ناموفق روی همان شناسه یا همان IP | ۰ یعنی همیشه |
| کپچا در فراموشی رمز | همیشه | پیش از ارسال پیامک یا ایمیل |
| هشدار | ۵۰ تلاش ناموفق در ۱۰ دقیقه | Push به superuserها و دارندگان مجوز؛ حداکثر یک‌بار در هر بازه |
| نگهداری گزارش | ۹۰ روز | پاک‌سازی روزانه ساعت ۳:۱۰ بامداد |

## کپچای داخلی
- تصویر روی همین سرور با Pillow و فونت Tahoma همراه پروژه ساخته می‌شود و به سرویس بیرونی وابسته نیست (`app/core/captcha.py`).
- پنج رقم فارسی با چرخش و خطوط نویز رسم می‌شوند. «۰» و «۱» در کپچا به کار نمی‌روند، چون «۰» فارسی یک نقطه است و «۱» با خط نویز اشتباه می‌شود.
- پاسخ با ارقام فارسی یا انگلیسی پذیرفته می‌شود.
- تصویر به‌صورت data URL از API می‌آید و فرانت آن را به آدرس `blob:` تبدیل می‌کند، چون CSP سرور (`img-src 'self' blob:`) تصویر `data:` را مسدود می‌کند.
- هر چالش یک‌بارمصرف است و ۳ دقیقه اعتبار دارد. فقط هش HMAC پاسخ (با `SECRET_KEY`) در `captcha_challenges` ذخیره می‌شود.
- `GET /auth/captcha?purpose=login|forgot`: برای `forgot`، اگر کپچای فراموشی رمز خاموش باشد، پاسخ `{required: false}` است.
- **ورود:** پاسخ 401 فیلد `captcha_required` دارد و فرانت با آن کادر کپچا را نشان می‌دهد. درخواست بعدی `captcha_id` و `captcha_answer` را می‌فرستد.
- **بعد از رفرش:** صفحه‌ی ورود هنگام باز شدن و با تغییر شناسه (با تأخیر ۵۰۰ میلی‌ثانیه) `GET /auth/captcha-status?identifier=` را صدا می‌زند. اگر همین IP یا همین شناسه به آستانه رسیده باشد، کپچا از همان ابتدا نمایش داده می‌شود.

## ترتیب بررسی در ورود
1. فهرست IPهای مجاز (قابلیت قبلی)
2. مسدودیت IP
3. قفل شناسه
4. کپچا (اگر لازم باشد)
5. رمز عبور

در شکست رمز عبور، شمارنده‌ی شناسه یکی زیاد می‌شود، رویداد ثبت می‌شود و سقف IP و آستانه‌ی هشدار بررسی می‌شوند. کپچای اشتباه در سقف IP شمرده می‌شود، ولی شمارنده‌ی شناسه را زیاد نمی‌کند.

## رفع قفل
- **صفحه‌ی امنیت ورود:** فهرست قفل‌های فعال (شناسه، IP و بازیابی رمز) با دکمه‌ی «رفع قفل». با آزادسازی یک IP، رویدادهای اخیرش هم دیگر در سقف IP شمرده نمی‌شوند، ولی در گزارش می‌مانند.
- **صفحه‌ی پرسنل:** در دیالوگ رمز عبور، دکمه‌ی «رفع قفل ورود» (`POST /employees/{id}/unlock-login`، با مجوز `users.manage` برای سایت همان پرسنل).

## گزارش
جدول `login_security_events` این رویدادها را ثبت می‌کند:
- `login_failed`: ورود ناموفق
- `login_locked`: تلاش روی شناسه‌ی قفل
- `ip_blocked`: مسدود شدن IP
- `captcha_failed`: کد امنیتی اشتباه
- `reset_code_failed`: کد بازیابی اشتباه
- `forgot_password`: درخواست بازیابی رمز

صفحه‌ی گزارش این بخش‌ها را دارد: خلاصه‌ی بازه، پرتکرارترین IPها و شناسه‌ها (با کلیک، فیلتر رویدادها پر می‌شود) و فهرست رویدادها با فیلتر و جست‌وجو.

## نکته‌ی IP پشت پراکسی
IP از `X-Forwarded-For` خوانده می‌شود (`get_client_ip`). اگر سرور مستقیم در دسترس باشد، این هدر قابل جعل است و کسی می‌تواند خودش را پشت یک IP معاف جا بزند. نکته‌ی `install.sh` درباره‌ی محدود کردن دسترسی مستقیم به سرور، برای IPهای معاف هم مهم است.

## دستگاه‌های هم‌زمان و «دستگاه‌های من» (Migration 115)

هر ورود موفق یک **نشست دستگاه** می‌سازد (`user_sessions`: برچسب دستگاه/مرورگر از User-Agent مثل «Chrome روی Windows» یا
«اپ اندروید» از هدر `X-Client-App`، IP، زمان ورود، آخرین فعالیت) و شناسه‌ی آن (`sid`) داخل Access و Refresh Token می‌نشیند.
هر درخواست، نشست را بررسی می‌کند؛ نشست باطل‌شده → 401 → فرانت به `/login?reason=signed_out` می‌رود و پیام «از این دستگاه
خارج شده‌اید» نشان می‌دهد. «آخرین فعالیت» حداکثر هر ۵ دقیقه یک بار به‌روز می‌شود.

- **سقف دستگاه هم‌زمان**: **هر کاربر خودش** در «دستگاه‌های من» سقفش را (۱ تا ۳) تعیین می‌کند (`PUT /auth/me/sessions/limit`
  → `users.max_sessions`)؛ تا وقتی تعیین نکرده، پیش‌فرض سیستم (تنظیمات امنیت ورود ← «دستگاه‌های هم‌زمان»، پیش‌فرض ۱).
  ادمین هم می‌تواند در تب «دستگاه‌ها» سقف هر نفر را عوض کند. ورود دستگاه جدید بیش از سقف، **قدیمی‌ترین نشست (بر اساس آخرین
  فعالیت)** را با دلیل `limit` خارج می‌کند؛ کم‌کردن سقف کسی را همان لحظه خارج نمی‌کند (فقط ورود بعدی).
- **خروج** (`POST /auth/logout`) فقط همین دستگاه را خارج می‌کند؛ دستگاه‌های دیگر وارد می‌مانند (قبلاً خروج همه را باطل می‌کرد).
- **دستگاه‌های من** (پنل کاربری ← «دستگاه‌های من»): فهرست دستگاه‌های فعال با علامت «این دستگاه»، خروج از راه دور هر دستگاه
  (`DELETE /auth/me/sessions/{id}`) و «خروج از همه‌ی دستگاه‌های دیگر» (`POST /auth/me/sessions/revoke-others`).
- **ادمین** (امنیت ورود ← تب «دستگاه‌ها»، مجوز `system.login_security`): همه‌ی نشست‌ها با جست‌وجو (نام کاربری/نام/کد/IP)،
  فقط فعال‌ها یا همه با دلیل خروج، خروج از راه دور (`DELETE /login-security/sessions/{id}`) و سقف اختصاصی هر کاربر
  (`PUT /login-security/users/{id}/max-sessions`).
- **تغییر رمز توسط خودِ کاربر**: بقیه‌ی دستگاه‌ها خارج می‌شوند، دستگاه جاری با توکن تازه ادامه می‌دهد. بازنشانی رمز/
  غیرفعال‌سازی توسط ادمین: همه‌ی نشست‌ها (`admin` / `deactivated`). نشست بدون فعالیت بیش از عمر رفرش‌توکن (۳۰ روز) `expired`.
- WebSocket حضور آنلاین هم نشست را بررسی می‌کند؛ دستگاه خارج‌شده «آنلاین» نمی‌ماند.
- **استقرار بدون خروج کسی**: توکن‌های قدیمی (بدون `sid`) تا انقضای ۶۰ دقیقه‌ای پذیرفته می‌شوند و در اولین تمدید، بی‌صدا
  نشست می‌گیرند (بدون اعمال سقف؛ `enforce_limit=False`). سقف از اولین ورود واقعی بعدی اعمال می‌شود.

فایل‌ها: `services/session_service.py`، `models/user_session.py`، `core/deps.py` (بررسی sid)، `core/security.token_pair`،
فرانت: `components/MyDevicesDialog.jsx`، تب «دستگاه‌ها» در `pages/LoginSecurityPage.jsx`.
