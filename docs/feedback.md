# انتقادات و پیشنهادات

قابلیت ارسال نظر/انتقاد/پیشنهاد توسط هر پرسنل — با امکان درخواست
ناشناس‌ماندن، مشروط به رعایت ادبیات مناسب.

## نکات کلیدی طراحی

- **دو مجوز مستقل**: `feedback.view` (سایت‌محور — فقط پیام‌های سایت
  خودش) و `feedback.view_all` (سراسری — همه سازمان). هر دو، طبق درخواست
  صریح، همان منطق محرمانگی/ناشناس‌بودن را رعایت می‌کنند — سراسری‌بودن
  دسترسی، به‌معنای دیدن هویت پیام‌های ناشناس نیست.
- **Admin واقعی (superuser) استثناست**: از پنل ادمین، همیشه فرستنده
  واقعی همه پیام‌ها را می‌بیند — صرف‌نظر از درخواست ناشناس‌ماندن — اما
  می‌بیند که کاربر خودش تیک ناشناس را زده بوده یا نه (یک Badge جداگانه).
- **الفاظ نامناسب یعنی شکستن ناشناسی**: اگر پیام حاوی هرکدام از عبارات
  فهرست «کلمات نامناسب» باشد، حتی اگر فرستنده تیک ناشناس را زده باشد،
  هویتش برای دارنده مجوز (نه فقط Admin) هم آشکار می‌شود.
- **فهرست کلمات نامناسب فقط دست Admin واقعی است** — نه حتی دارنده مجوز
  مشاهده، چون او خودش ذی‌نفع این فهرست است (می‌توانست با ویرایش فهرست،
  عملاً محرمانگی را دور بزند).

## معماری Backend

### مدل‌ها (Migration 040)

- `FeedbackMessage`: `sender_id` (همیشه ثبت می‌شود، حتی برای پیام‌های
  ناشناس)، `message`، `is_anonymous_requested`، `contains_profanity`
  (در لحظه ارسال محاسبه و ذخیره می‌شود - تغییر بعدی فهرست کلمات
  نامناسب روی پیام‌های قبلی اثر نمی‌گذارد).
- `ProhibitedPhrase`: فهرست ساده کلمات/عبارات.

### منطق افشای فرستنده (`feedback_service.py`)

```python
reveal_sender = is_superuser or not is_anonymous_requested or contains_profanity
```

جدول درستی این عبارت با تست پوشش کامل شد (۴ حالت: سوپریوزر، غیرناشناس،
ناشناس+تمیز، ناشناس+رکیک).

### دسترسی سایت‌محور/سراسری (`_get_accessible_scope`)

هر دو مجوز (`feedback.view`، `feedback.view_all`) چک و ترکیب می‌شوند —
اگر هرکدام به‌صورت سراسری اختصاص یافته باشد، دسترسی نامحدود است؛ وگرنه
اتحاد سایت‌های هر دو مجوز.

### `require_superuser` (Dependency جدید در `app/core/deps.py`)

برخلاف `require_permission`، هیچ Permission Code ای قبول نمی‌کند — فقط
Admin واقعی. برای مدیریت فهرست کلمات نامناسب استفاده می‌شود.

### `can_view_feedback` در `/auth/me`

`True` اگر Admin واقعی باشد یا هرکدام از دو مجوز را (در هر سایتی) داشته
باشد — فقط برای نمایش/مخفی‌کردن منو، نه اجرای واقعی محدودیت (که در
خودِ Endpoint انجام می‌شود).

## Frontend

- **`FeedbackSubmitDialog.jsx`**: دیالوگ ارسال، از کارت «انتقادات و
  پیشنهادات» در داشبورد شخصی باز می‌شود (قبلاً «به‌زودی» بود، حالا فعال
  است). تیک‌زدن «ارسال به‌صورت ناشناس» بلافاصله فعال نمی‌شود - اول متن
  اطمینان‌بخشی (دقیقاً متن درخواستی) در یک دیالوگ جدا نمایش داده
  می‌شود؛ فقط با کلیک «موافقم» چک‌باکس واقعاً فعال می‌شود.
- **`FeedbackReportPage.jsx`** (مسیر `/feedback-report`): فهرست پیام‌ها
  — برای Admin واقعی، یک تب اضافی «مدیریت کلمات نامناسب» هم نمایش داده
  می‌شود (افزودن/حذف عبارت).
