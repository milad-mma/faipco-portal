# ویژگی‌ها

## مدیریت پرسنل و سازمان

- **Sync خودکار پرسنل** از دیتابیس‌های ناهمگون هر سایت (SQL Server / MySQL /
  PostgreSQL) — بدون نیاز به تغییر کد برای سایت جدید، فقط با تعریف Mapping
  ستون‌ها از پنل. فاصله زمانی اجرای خودکار و تاریخچه هر اجرا از داخل پنل
  قابل مشاهده و تنظیم است.
- **واحدهای سازمانی (Department)** با تعیین سرپرست — سرپرست هر واحد بدون
  نیاز به تعریف نقش RBAC جداگانه، می‌تواند برای پرسنل همان واحد اطلاعیه
  بفرستد.
- **مدیریت پرسنل از پنل**: فعال/غیرفعال کردن دستی (مستقل و جدا از وضعیت
  `is_active` که کاملاً تحت مالکیت Sync است)، تعیین رمز عبور ورود، مشاهده و
  Sort بر اساس سایت/واحد سازمانی.
- **لاگین یکپارچه**: هم ورود مدیریتی (یوزرنیم/رمز عبور) و هم ورود پرسنل (کد
  پرسنلی + کد ملی) از یک فرم واحد.

## اطلاعیه‌ها

- تعیین دقیق مخاطب: کل سازمان / یک سایت / یک یا چند واحد سازمانی / یک نقش /
  پرسنل خاص — همراه با آمار بازدید، Web Push، و حذف (Soft-Delete، با
  نگه‌داشتن رکورد در گزارش برای حفظ آمار).
- **اطلاعیه فیش حقوقی**: آپلود یک فایل XML فیش حقوق (نقش `acc_manager`)،
  تطبیق خودکار با پرسنل از روی کد پرسنلی، و ارسال PDF جداگانه به هر نفر —
  هرکس فقط فیش خودش را می‌بیند (جداسازی ساختاری، نه فقط بررسی مجوز).
- **اطلاعیه فیش کارکرد**: مشابه فیش حقوقی، ولی از فایل اکسل (XLSX) با
  تشخیص محدوده ستون‌ها.
- **گزارش اطلاعیه‌های ارسالی**: چه کسی، چه زمانی، برای چه کسانی فرستاده و
  چند نفر دیده‌اند — با نمایش کارتی اختصاصی روی موبایل (بدون اسکرول افقی)
  و جدول کامل روی دسکتاپ.
- **محدودیت ارسال پیاپی**: هر کاربر حداکثر یک اطلاعیه در هر ۶۰ ثانیه —
  به‌صورت مشترک بین همه Worker های سرویس (نه فقط درون‌حافظه‌ای).

## دسترسی و امنیت (RBAC)

- **RBAC چندلایه**: نقش‌های سراسری، نقش‌های محدود به یک سایت (Site-scoped)،
  و سرپرستی واحد سازمانی.
- **انتصاب دسته‌جمعی نقش**: یک نقش را هم‌زمان به همه پرسنل یک سایت یا یک
  واحد سازمانی اختصاص می‌دهد — پرسنلی که هنوز هیچ‌وقت وارد پرتال نشده هم
  حساب کاربری‌اش خودکار ساخته می‌شود.
- **قفل موقت ورود** بعد از تلاش‌های ناموفق پیاپی (۳ تلاش → ۶۰ ثانیه، ۶ تلاش
  → ۵ دقیقه، ۹+ تلاش → ۱ ساعت) — شمارنده در دیتابیس (نه درون‌حافظه‌ای)، پس
  بین همه Worker های سرویس مشترک و قابل‌اعتماد است.
- **رنج‌های IP مجاز (ضدVPN)**: محدودکردن ورود به رنج‌های IP مشخص، با پیام
  قابل‌تنظیم برای کاربران مسدودشده.
- **هدرهای امنیتی HTTP کامل**: HSTS، CSP، Permissions-Policy، X-Frame-Options،
  X-Content-Type-Options، Referrer-Policy — تنظیم‌شده مخصوص همین پروژه (نه
  یک فرمول عمومی)، بدون هیچ وابستگی به CDN خارجی (فونت هم Self-Host است).

## حضور و ورود/خروج (GPS)

- **حضور آنلاین زنده** با WebSocket — مشابه یک سیستم چت، فقط وقتی پرسنل
  داخل محدوده جغرافیایی تعریف‌شده سایت باشد ثبت می‌شود.
- **ثبت ورود/خروج آزمایشی مبتنی بر GPS** برای نقش `attendance-pilot` — با
  گزارش گروه‌بندی‌شده بر اساس روز و پشتیبانی از چند نوبت ورود/خروج در روز.

## پیام تبریک تولد

- ارسال خودکار روزانه در ساعت قابل‌تنظیم، با استخر پیام‌های تصادفی
  قابل‌مدیریت از پنل — قفل‌شده بین Worker ها (بدون خطر ارسال تکراری).

## پشتیبان‌گیری و بازیابی

- **بکاپ کامل** (Schema + Data) با یک کلیک از پنل.
- **بازیابی از پنل**، فقط روی همین سرور — با نمایش لاگ زنده حین اجرا، و
  Rollback خودکار کامل در صورت هر خطا (بدون باقی‌ماندن در حالت نیمه‌خراب).

## بررسی و اعمال آپدیت از پنل

- مقایسه خودکار نسخه فعلی با آخرین Tag منتشرشده در GitHub.
- اعمال آپدیت مستقیم از پنل (معادل اجرای `sudo bash install.sh` از راه دور)
  با نمایش لاگ زنده، پشت تأیید رمز عبور دوباره (مستقل از Session ورود).

## PWA و اعلان‌ها

- نصب به‌عنوان یک اپلیکیشن مستقل (PWA) روی موبایل/دسکتاپ — Service Worker
  با `vite-plugin-pwa` (استراتژی injectManifest) ساخته می‌شود، با
  Precache خودکار App Shell (جزئیات در [`docs/pwa.md`](pwa.md)).
- Push Notification (Web Push / VAPID) با به‌روزرسانی خودکار Service Worker
  بدون نیاز به خروج کاربر از حساب.

## نصب و استقرار

- **نصب یک‌دستوری** روی Ubuntu Server با `install.sh` (نصب یا آپدیت،
  به‌صورت خودکار تشخیص داده می‌شود؛ همان اسکریپت هم از خط‌فرمان و هم از
  دکمه «آپدیت» داخل پنل استفاده می‌شود).
- نسخه فعلی از تگ Git واقعی خوانده و در صفحه ورود نمایش داده می‌شود — بدون
  نیاز به SSH برای تأیید اینکه آخرین Deploy واقعاً نشسته.
