# کد تأیید (OTP) برای تغییر رمز عبور و شماره موبایل

از Migration **112** (جدول `verification_codes`).

## تغییر رمز اجباری اولین ورود

در پنجره‌ی اجباری اولین ورود (رمز پیش‌فرض) **هیچ کدی فرستاده نمی‌شود** و به موبایل/ایمیل کاری ندارد؛ فقط
«رمز عبور فعلی» (همان رمز پیش‌فرض، برای پرسنل = کد ملی) و رمز جدید پرسیده می‌شود. سرور هم در این وضعیت
(`must_change_password` یا پرسنل بدون رمز اختصاصی) کد نمی‌خواهد (`otp_service.is_mandatory_password_change`).

## تغییر رمز عبور از صفحه‌ی پروفایل

به‌جای «رمز عبور فعلی»، یک **کد ۶ رقمی** با پیامک یا ایمیل فرستاده می‌شود.

| وضعیت کاربر | روش تأیید |
|---|---|
| موبایل دارد و سرویس پیامک روشن است | کد پیامکی |
| ایمیل دارد و سرویس ایمیل (SMTP) روشن است | کد ایمیلی |
| هر دو | کاربر با دکمه‌ی رادیویی انتخاب می‌کند (پیش‌فرض پیامک) |
| هیچ‌کدام (یا هر دو سرویس خاموش) | مثل قبل: «رمز عبور فعلی» (برای پرسنل بدون رمز اختصاصی = کد ملی) |

مثال: علی موبایل 09121234567 دارد → در دیالوگ «ارسال کد با پیامک» را می‌زند، پیام «کد تأیید به 0912***4567 ارسال شد»
را می‌بیند، کد را وارد و رمز جدید را ثبت می‌کند.

> اگر موبایل ثبت‌شده‌ی کسی اشتباه باشد و ایمیل هم نداشته باشد، کد به دستش نمی‌رسد؛ باید موبایلش در کاراوب/پرتال
> اصلاح شود یا ادمین رمزش را بازنشانی کند. (این فقط برای تغییر رمز از پروفایل است، نه اولین ورود.)

## تغییر شماره موبایل (دیالوگ «مشخصات کاربری»)

- کد فقط با **پیامک** و به **شماره‌ی جدید** فرستاده می‌شود و فقط برای همان شماره معتبر است
  (اگر بعد از ارسال، شماره را عوض کنید باید دوباره «ارسال کد» بزنید).
- اگر سرویس پیامک در پنل خاموش باشد، مثل قبل «رمز عبور فعلی» پرسیده می‌شود.
- **تغییر ایمیل هیچ تأییدی نمی‌خواهد** (نه کد، نه رمز).

## قواعد امنیتی

- عمر کد: ۵ دقیقه. ارسال دوباره: بعد از ۶۰ ثانیه (پاسخ 429 با `Retry-After`).
- حداکثر ۵ کد اشتباه؛ بعد کد باطل می‌شود.
- با هر ارسال جدید، کدهای قبلی همان هدف باطل می‌شوند. فقط هش SHA-256 کد ذخیره می‌شود.
- قدرت رمز جدید قبل از مصرف کد بررسی می‌شود (با رمز ضعیف، کد هدر نمی‌رود).
- ارسال ناموفق (مثلاً قطعی درگاه پیامک) با پیام فارسی نمایش داده می‌شود و ردیف کد حذف می‌شود تا بلافاصله بتوان دوباره امتحان کرد.

## API

| مسیر | توضیح |
|---|---|
| `GET /auth/me/password/otp-options` | `{otp_required, channels: {sms?, email?}, sms_enabled, code_ttl_seconds, resend_cooldown_seconds}` |
| `POST /auth/me/password/otp` | بدنه `{channel: "sms"\|"email"}` → `{masked_contact, expires_in_seconds, resend_cooldown_seconds}` |
| `PUT /auth/me/password` | `{otp_code?, current_password?, new_password}` — اگر `otp_required` باشد `otp_code` لازم است |
| `POST /auth/me/mobile/otp` | بدنه `{mobile}` (شماره‌ی جدید) |
| `PUT /auth/me/contact-info` | `{email?, mobile, mobile_otp_code?, current_password?}` |
