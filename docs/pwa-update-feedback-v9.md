# FAIPCO Portal v9 — PWA update feedback and connection messaging

این نسخه روی **v8** ساخته شده و تغییرات آن فقط محدود به تجربه‌ی به‌روزرسانی/تازه‌سازی برنامه، تشخیص پیام قطع ارتباط، مستندات و تست‌های مربوط است.

## ۱) کاربر: اعلان به‌روزرسانی در مرورگر و TWA اندروید

| وضعیت | متن بالای اعلان | متن زیر آن | متن دکمه |
|---|---|---|---|
| نصب کامل نسخه جدید و Service Worker در حالت `waiting` | به‌روزرسانی پرتال آماده است | برای استفاده از آخرین نسخه پرتال، «بارگذاری» را انتخاب کنید. | بارگذاری |
| آماده‌شدن تازه‌سازی فایل‌ها، بدون تغییر لزوماً در شماره نسخه | به‌روزرسانی پرتال آماده است | برای تازه‌سازی فایل‌های برنامه، «بارگذاری» را انتخاب کنید. اطلاعات حساب شما حذف نمی‌شود. | بارگذاری |
| بعد از لمس دکمه، پیش از تغییر کنترل Service Worker | به‌روزرسانی پرتال آماده است | در حال آماده‌سازی و فعال‌کردن نسخه جدید... | در حال به‌روزرسانی... |
| Service Worker فعال شد و پرتال در حال بازشدن مجدد است | به‌روزرسانی پرتال آماده است | نسخه آماده شد؛ پرتال در حال باز شدن دوباره است... | در حال باز شدن... |
| بعد از بارگذاری مجدد موفق از انتشار نسخه | — | نسخه جدید پرتال با موفقیت بارگذاری شد. | — |
| بعد از بارگذاری مجدد موفق از تازه‌سازی فایل‌ها | — | پرتال با موفقیت دوباره بارگذاری شد. | — |
| Worker در زمان لمس آماده نباشد | به‌روزرسانی کامل نشد | فایل‌های به‌روزرسانی هنوز آماده نیستند. کمی بعد دوباره تلاش کنید. | تلاش دوباره |
| فعال‌سازی بیش از ۱۲ ثانیه طول بکشد | به‌روزرسانی کامل نشد | بارگذاری نسخه جدید طولانی شد. دوباره تلاش کنید. | تلاش دوباره |
| مرورگر از Service Worker پشتیبانی نکند | به‌روزرسانی کامل نشد | به‌روزرسانی خودکار در این مرورگر پشتیبانی نمی‌شود. صفحه را دوباره باز کنید. | تلاش دوباره |
| خطای غیرمنتظره فعال‌سازی | به‌روزرسانی کامل نشد | بارگذاری به‌روزرسانی انجام نشد. دوباره تلاش کنید. | تلاش دوباره |

پس از کلیک روی «بارگذاری»، دکمه فوراً غیرفعال و دارای نشانگر فعالیت می‌شود؛ لمس تکراری دوباره اعمال نمی‌شود. فقط بعد از `controllerchange` واقعی، رسید موقت داخل `sessionStorage` ثبت و صفحه مجدداً بارگذاری می‌شود. پس از بارگذاری، رسید یک‌بار خوانده/حذف و پیام موفقیت ۶٫۵ ثانیه نمایش داده می‌شود. توکن، نشست و مسیر جاری دستکاری نمی‌شوند؛ حذف کش عمومی انجام نمی‌شود.

**محدودیت:** تازه‌سازی Service Worker الزاماً به معنای تغییر فوری آیکون نصب‌شده اندروید نیست.

## ۲) مدیر: صفحه بررسی و اعمال آپدیت

| شرایط | متن نمایش داده شده |
|---|---|
| در حال بررسی | در حال بررسی... |
| GitHub یا اتصال بررسی در دسترس نباشد | امکان بررسی آپدیت نبود — اتصال اینترنت یا GitHub در دسترس نیست. نسخه فعلی: «نسخه جاری» | 
| آپدیت در دسترس | نسخه جدید «شماره نسخه» در دسترس است — نسخه فعلی شما: «شماره نسخه» |
| آخرین نسخه نصب است | شما آخرین نسخه را دارید («شماره نسخه») |
| ورودی تأیید نادرست | برای تأیید، دقیقاً «UPDATE» را تایپ کنید. |
| رمز عبور خالی | رمز عبور فعلی خودتان را وارد کنید. |
| اجرای نصب | در حال آپدیت — این بخش هر چند ثانیه یک‌بار به‌صورت خودکار به‌روزرسانی می‌شود. سرویس چند لحظه در دسترس نخواهد بود. |
| روی دکمه هنگام نصب | در حال آپدیت... |
| پایان موفق نصب | آپدیت با موفقیت انجام شد. — اکنون صفحه به‌طور خودکار بازخوانی می‌شود. |
| شکست نصب | آپدیت با خطا مواجه شد — جزئیات کامل در لاگ زیر است. |
| وضعیت نامشخص پس از بازیابی سرویس | فرآیند آپدیت تمام شد و سرویس بالا است، ولی پیام نهایی در لاگ ثبت نشد. صفحه بازخوانی می‌شود؛ نسخه را بررسی کنید. |
| بیشتر از مدت پیگیری | بعد از چند دقیقه هنوز نتیجه مشخص نشد — لطفاً دستی از سرور چک کنید: sudo cat /var/log/faipco-install.log |
| شکست درخواست شروع نصب | متن خطای API (در صورت وجود) یا «آپدیت با خطا مواجه شد.» |

نمایش توضیح کانال آپدیت `tag/branch`، هشدار اثر نصب بر سرویس، ورودی‌های رمز و `UPDATE` و خروجی لاگ همچنان همان نسخه v8 است. وضعیت `isUpdating` در صفحه مدیر اکنون هنگام Restart سرور، هشدار اشتباه قطعی اینترنت را موقتاً غیرفعال می‌کند.

## ۳) مدیر: کارت تازه‌سازی برنامه برای کاربران

| شرایط | متن |
|---|---|
| عنوان کارت | تازه‌سازی برنامه برای کاربران |
| توضیح | اگر برخی کاربران هنوز صفحه‌های قدیمی پرتال را می‌بینند، از این گزینه استفاده کنید. پس از آماده‌شدن فایل‌های برنامه، اعلان «به‌روزرسانی پرتال آماده است» برای کاربران نمایش داده می‌شود. برنامه فقط با انتخاب «بارگذاری» توسط خود کاربر دوباره باز می‌شود. حساب کاربری و اطلاعات ثبت‌شده حذف نمی‌شوند. تغییر فوری آیکون نصب‌شده در اندروید تضمین‌شده نیست. |
| دکمه پیش از شروع | اعلان تازه‌سازی به کاربران |
| دکمه هنگام ارسال | در حال ثبت درخواست... |
| رویداد اطلاع‌رسانی با موفقیت منتشر شد | درخواست تازه‌سازی پرتال ثبت و پیام اطلاع‌رسانی ارسال شد. پس از آماده‌شدن فایل‌ها، کاربران آنلاین اعلان «به‌روزرسانی پرتال آماده است» را می‌بینند. دیگر کاربران هنگام بازگشت به پرتال بررسی می‌شوند. حساب کاربری و اطلاعات ذخیره‌شده کاربران حذف نمی‌شود. |
| Worker سرور تغییر کرد ولی اطلاع‌رسانی آنی ناموفق بود | درخواست تازه‌سازی پرتال ثبت شد، اما ارسال پیام آنی موفق نبود. کاربران هنگام بازگشت به پرتال یا اتصال دوباره، نسخه را بررسی می‌کنند. حساب کاربری و اطلاعات ذخیره‌شده کاربران حذف نمی‌شود. |
| خطای ارسال درخواست | متن خطای API (در صورت وجود) یا «درخواست تازه‌سازی پرتال انجام نشد. دوباره تلاش کنید.» |

موفقیت پیام آنی به معنی *ارسال رویداد* است، نه تأیید دیده‌شدن آن توسط تمام کاربران. کاربران آفلاین با بازگشت به برنامه/اتصال مجدد بررسی می‌شوند.

## ۴) ارتباط در زمان آپدیت و هنگام قطعی واقعی

| شرایط | پیام و رفتار |
|---|---|
| اعمال انتشار در همان صفحه مدیریتی | بنر سراسری قطع ارتباط نشان داده نمی‌شود؛ پیام «در حال آپدیت...» در همان صفحه فعال است |
| کلیک کاربر روی بارگذاری Service Worker | بنر سراسری قطع ارتباط نشان داده نمی‌شود؛ وضعیت پیشرفت در اعلان آپدیت نمایش داده می‌شود |
| قطعی کوتاه `/api/health` هنگام Restart سرویس برای سایر کاربران | به مدت ۶ ثانیه فرصت بازیابی؛ اگر برنگشت، هشدار زرد: «ارتباط با سرور پرتال موقتاً برقرار نیست. ممکن است سرور در حال به‌روزرسانی باشد؛ کمی بعد دوباره تلاش کنید.» |
| قطع اینترنت اعلام‌شده توسط مرورگر | اگر بیش از ۲٫۵ ثانیه ادامه داشت، هشدار قرمز: «اتصال اینترنت دستگاه برقرار نیست. بعضی تغییرات ممکن است ذخیره نشوند.» |
| بازگشت ارتباط به حالت سالم | پیام قطع ارتباط خودکار مخفی می‌شود |
| خطای موقت `/auth/me` پس از بازشدن مجدد | صفحه احراز هویت بازیابی حفظ می‌شود: «در حال بازیابی اتصال پرتال» و «ارتباط با سرور موقتاً برقرار نشد. اطلاعات ورود شما حفظ شده است و پرتال به‌صورت خودکار دوباره تلاش می‌کند.» دکمه: «تلاش دوباره» یا «در حال بررسی اتصال...» |

**تمایز مهم:** خراب‌شدن `/api/health` هنگام Restart شدن Backend نشان‌دهنده‌ی خراب‌شدن اینترنت گوشی نیست. این اصلاح عمداً از اظهار نادرست «اینترنت قطع شده» جلوگیری می‌کند. هیچ تلاشی برای حدس‌زدن قطعی سرور بدون شواهد یا نمایش درصد ساختگی پیشرفت صورت نمی‌گیرد.

## ۵) دامنه تغییرات و تست

- مسیرهای API و قوانین RBAC همان v8 باقی مانده‌اند.
- WebSocket حضور/GPS، Web Push، اعلان استخدام، مرخصی، اتوماسیون، شیفت، عکس پرسنل، دریافت فیش و منطق بیمه تغییر داده نشده است.
- ۳۸ تست واحد Frontend (شامل ۱۰ تست تازه/افزوده) و ۷ تست Backend مرتبط موفق شدند.
- Parse تمامی ۷ فایل JS/JSX تغییر یافته موفق بود؛ Build تولیدی به دلیل در دسترس نبودن وابستگی npm در این محیط تأیید نشد.
- آزمایش واقعی TWA اندروید و عملکرد Nginx/PostgreSQL بر روی سرور هنوز باید انجام شود.
