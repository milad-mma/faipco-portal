# ماژول همکاری با ما / استخدام فایپکو (نسخه توسعه‌ای برای تست)

## فایل‌ها و مسیرها
- `/careers`: صفحه عمومی و فرم استخدام، بدون نیاز به لاگین و بدون پیگیری متقاضی.
- `/careers/admin`: پنل منابع انسانی؛ لیست صفحه‌بندی‌شده، فیلتر وضعیت، درج نظریه واحد اداری و ویرایش متن عمومی.
- `/careers/admin/print/:id`: پیش‌نمایش مستقل A4 بر پایه ترتیب بخش‌های «پرسشنامه استخدامی ۱۴۰۴» و چاپ از مرورگر (`window.print()` / Save as PDF). قالب برای فرم آنلاین بازسازی شده؛ کپی پیکسلی Word نیست.
- `/api/v1/careers/...`: API عمومی و APIهای دارای مجوز. از مسیر `/careers/admin` برای متقاضی استفاده نکنید.

## نصب / مهاجرت
1. از PostgreSQL و فایل‌های پرتال پشتیبان بگیرید.
2. کد را در **سرور تست** نصب کنید و به‌روز بودن وابستگی‌ها را تضمین کنید. به‌ویژه `python-multipart==0.0.33` برای رفع مشکلات امنیتی نسخه قبلی 0.0.9 لازم است.
3. در پوشه `backend`: `alembic upgrade head`. دو migration افزوده شده: **116** (جداول استخدام) و **117** (مجوز منابع انسانی).
4. `CAREERS_RESUME_DIR` را به پوشه‌ای جدا از پوشه public وب‌سرور تنظیم کنید، با مجوز خواندن/نوشتن صرفاً برای کاربر سرویس Backend. برای SMB: اول share را به‌شکل امن mount و سپس مسیر mount را تنظیم کنید. فایل‌ها با نام تصادفی و سطح دسترسی `0600` نگهداری می‌شوند. **پوشه رزومه را بکاپ بگیرید**.
5. ترجیحاً ClamAV روی سرور یا LAN فعال باشد. با تنظیم `CAREERS_CLAMAV_SOCKET=/run/clamav/clamd.ctl` بررسی فایل به‌صورت اجباری و fail-closed انجام می‌شود؛ بدون تنظیم، فقط بررسی اولیه محتوای PDF فعال است و این **جایگزین اسکن آنتی‌ویروس نیست**.
6. `CAREERS_RATE_LIMIT_SECRET` اختیاری است؛ در نبودش از SECRET_KEY امن پرتال برای HMAC IP استفاده می‌شود.
7. در «مدیریت نقش‌ها» یا «مجوز مستقیم کاربران»، کد **`careers.manage`** را فقط به مسئولان مجاز واحد منابع انسانی **با محدوده سراسری (site_id=NULL)** اعطا کنید. مجوز سایت‌محور برای دیدن همه متقاضیان عمداً کار نمی‌کند زیرا فرم عمومی به سایت خاصی منتسب نشده است. Superuser به‌طور پیش‌فرض دسترسی دارد.
8. Frontend را با `npm install` و `npm run build` در محیطی با دسترسی به package registry بسازید و برنامه را برای تست بالا بیاورید.

## اعلان استخدام
- هنگام ثبت موفق درخواست، Web Push با متن غیرشخصی «درخواست استخدام جدیدی ثبت شده است» به سوپریوزرها و دارندگان مجوز سراسری `careers.manage` ارسال می‌شود. دریافت Push مستلزم تنظیم کلیدهای VAPID و فعال بودن اشتراک اعلان هر دستگاه است. اگر Push فعال نیست، ثبت درخواست تحت تأثیر قرار نمی‌گیرد.
- در هنگام باز بودن پرتال، UI هر دقیقه یک‌بار آخرین شناسه درخواست را بررسی کرده و در صورت افزایش آن پیام اعلان نمایش می‌دهد؛ داده شخصی در متن اعلان یا endpoint polling وجود ندارد.
- اعلان‌های Push به‌صورت background best-effort هستند؛ **صف تضمین تحویل/durable queue** برای تحویل در شرایط قطع سرویس یا اینترنت هنوز وجود ندارد. پرونده همیشه در لیست ذخیره‌شده قابل مشاهده است.

## فرم و فایل رزومه
- جنسیت، دین، مذهب، وضعیت سلامت، سابقه جراحی، سیگار و مهارت/تحصیلات/سوابق در فرم وجود دارند؛ وضعیت نظام‌وظیفه فقط در صورت انتخاب جنسیت مرد الزامی است.
- شماره بیمه اختیاری است. بخش نظریه سرپرست حذف شده و «نظریه واحد اداری / منابع انسانی» در پنل داخلی باقی است.
- فقط رزومه **PDF** با حجم حداکثر ۳ مگابایت پذیرفته می‌شود. هیچ فایل اجرایی یا Word/ZIP در این نسخه قابل ارسال نیست. فایل دانلودشده با Content-Disposition: attachment و nosniff بازگردانده می‌شود و نیازمند مجوز HR است.
- هیچ حساب کاربری، کد رهگیری یا پرتال پیگیری برای متقاضی ساخته نمی‌شود.

## امنیت ویژه مسیر عمومی
- دسترسی تمام endpointهای پرونده/چاپ/رزومه و ویرایش متن فقط با مجوز سمت سرور؛ هیچ اطلاعات حساس در API عمومی صفحه نمایش داده نمی‌شود.
- اعتبارسنجی سمت Backend: مقادیر Enum، نظام وظیفه مشروط، حداقل یک سابقه در صورت داشتن سابقه، طول فیلدها، ردیف‌های تکراری، رضایت صریح و honeypot.
- محدودیت سه درخواست *موفق* در ساعت به ازای IP و محدودیت ثبت مجدد برای همان تلفن/شغل در ۲۴ ساعت. شمارش در PostgreSQL است و برای جلوگیری از race، قفل تراکنشی استفاده شده است. IP واقعی از تابع proxy-aware مورد استفاده سایر بخش‌های پرتال دریافت می‌شود.
- محدودیت حجم Body و فایل داخل endpoint در نظر گرفته شده؛ با این حال **parser وب‌سرور پیش از اجرای endpoint می‌تواند محتوا دریافت کند**. حتماً در Nginx نیز `client_max_body_size 4m;` و `limit_req` روی دو POST `/api/v1/careers/apply` و `/api/v1/careers/apply-with-resume` قرار گیرد (مثلاً نرخ ۵ در دقیقه/IP با burst محدود). قوانین Nginx را با تنظیمات اصلی و reverse proxy نصب‌شده ادغام کنید، نه جایگزین کل config.
- Uvicorn را مستقیم در اینترنت باز نکنید؛ فقط از پروکسی معتبر استفاده کنید. مراقب هدرهای X-Real-IP و X-Forwarded-For باشید. ارتباط HTTPS الزامی است.
- توصیه عملیاتی: دسترسی به گزارش‌ها و بکاپ‌ها را محدود کنید، سیاست زمان نگهداری فرم‌ها/رزومه‌ها تعیین کنید، فایل‌های قدیمی را پس از پایان مهلت قانونی حذف کنید و به علت داده‌های حساس دینی و سلامت، رضایت و دسترسی را با مسئول حقوقی/منابع انسانی ارزیابی کنید.

## آزمون‌ها و محدودیت‌های شناخته‌شده
- بررسی نحوی همه فایل‌های Python (`compileall`) و parse هشت فایل JSX تغییرکرده انجام شده است.
- `python backend/tests/api_snapshot.py` پس از به‌روزرسانی Snapshot مسیرها موفق شد (۴۲۵ مسیر).
- ۱۹ تست قواعد مساعده و وام اجرا و پاس شدند. سناریوهای مستقل اعتبارسنجی فرم (۱ ورودی معتبر، ۵ سناریوی مردود) نیز اجرا و پاس شدند.
- تست integration واقعی API، اتصال PostgreSQL، migration واقعی، آپلود روی SMB، ارسال Push واقعی، اسکن ClamAV و چاپ Chrome/PDF روی سرور کاربر هنوز اجرا **نشده‌اند**.
- `npm install` به علت نبود دسترسی package registry در محیط آماده‌سازی تکمیل نشد؛ لذا Build Vite هنوز تأیید نشده است. تست اجرای API هم به دلیل عدم نصب `asyncpg` در این محیط متوقف شد. این نسخه برای **سرور تست** است و تأیید امنیتی Production محسوب نمی‌شود.
- فایل Word اصلی خوانده شد؛ ساختار شماره‌گذاری و بخش‌های آن مبنای قالب چاپ است. سورس اجرایی کامپوننت چاپ نامه‌های اتوماسیون در این Snapshot موجود نبود (فقط اسناد طراحی اتوماسیون در بعضی نسخه‌های دیگر پروژه موجودند)، بنابراین انطباق عینی با UI چاپ اتوماسیون هنوز نیازمند مقایسه هنگام تست است.
