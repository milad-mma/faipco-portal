# دو روش دریافت فیش حقوقی و فیش کارکرد (Browser Print + Server PDF)

وضعیت: پیاده سازی شده در کد؛ آزمون جامع مرورگرها، تطبیق دقیق ظاهر و تست فشار روش جدید هنوز انجام نشده است.

## هدف

در صفحه اطلاعیه های فیش حقوقی و فیش کارکرد، برای کارمند دارای فیش دو گزینه نمایش داده می شود:

1. **چاپ / ذخیره PDF (مرورگر)**: روش پیش فرض. API فقط داده همان کارمند را بازمی گرداند؛ صفحه HTML با CSS چاپ A4 در پنجره جدید نمایش داده شده و کاربر از گزینه Print / Save as PDF مرورگر استفاده می کند.
2. **دانلود PDF (روش جایگزین)**: مسیر پیشین و دست نخورده دانلود فایل تولیدشده با ReportLab در Backend.

هیچ تغییری در سازوکار بارگذاری، انتشار یا داده های اصلی فیش ها و هیچ Migration جدیدی برای این قابلیت لازم نیست.

## مسیرها

| نوع | اطلاعات برای چاپ مرورگر | PDF سمت سرور (قبلی) |
| --- | --- | --- |
| حقوقی | `GET /api/v1/notices/{notice_id}/payroll/mine/print-data` | `GET /api/v1/notices/{notice_id}/payroll/mine` |
| کارکرد | `GET /api/v1/notices/{notice_id}/attendance-card/mine/print-data` | `GET /api/v1/notices/{notice_id}/attendance-card/mine` |

تمام مسیرها نیازمند احراز هویت و مجوز دسترسی هستند؛ درخواست چاپ نیز اطلاعیه معتبر و فیش متعلق به کارمند متصل را بررسی می کند. API جدید فقط داده فیش شخص جاری را برمی گرداند، نه اطلاعات کل کارکنان.

## محل تغییرات

- `backend/app/api/v1/endpoints/notices.py`: دو endpoint فقط-خواندنی `print-data`.
- `frontend/src/api/receiptPrint.js`: درخواست داده چاپ از API.
- `frontend/src/services/receiptBrowserPrint.js`: ساخت HTML و CSS چاپ، نمایش پنجره و فراخوانی `window.print()`.
- `frontend/src/pages/NoticesPage.jsx`: نمایش دو دکمه برای هر دو نوع فیش و حفظ دانلود قبلی.

## رفتار و محدودیت ها

- در مرورگر ابتدا پنجره جدید باز می شود تا احتمال مسدود شدن popup پس از درخواست async کمتر شود؛ در صورت مسدود شدن باید خطای قابل فهم نمایش داده شود.
- مسیر چاپ مرورگر به انتخاب Print / Save as PDF توسط کاربر وابسته است؛ خروجی یکسان پیکسلی در همه موتورهای چاپ تضمین نشده و باید با نمونه ReportLab سنجیده شود.
- روش جایگزین ReportLab همچنان فعال است و برای بررسی اختلافات و موارد ناسازگاری قابل استفاده خواهد بود.
- داده های فیش حساس هستند. خروجی JSON نباید در لاگ مرورگر، تحلیلگر، کش عمومی یا سرویس خارجی ذخیره شود؛ در صورت تغییر در کنترل دسترسی، هر دو مسیر باید همزمان بازبینی شوند.
- باز شدن پنجره جدید، فونت فارسی، جهت اعداد، اندازه A4، چاپ رنگ پس زمینه، برش صفحات، لوگو و تجربه ذخیره روی iOS/Safari و Android/TWA باید عملی تست شوند.

## آزمون پذیرش پیش از استقرار اصلی

1. برای هر دو فیش، خروجی PDF قبلی را با چاپ مرورگر در Chrome، Edge، Firefox، Opera و Safari مقایسه تصویری کنید.
2. دانلود/ذخیره را روی Windows، Android (مرورگر و اپ TWA) و iOS (Safari / PWA) بررسی کنید؛ چاپ A4، فارسی و داده مالی دقیق باشند.
3. با کاربر بدون فیش و حساب دیگر، هر دو API باید دسترسی غیرمجاز را رد کنند.
4. در Load Test، API `print-data` را با API PDF قدیمی مقایسه کنید. Locust صرفا پاسخ HTTP را تست می کند و موتور چاپ واقعی مرورگر را اجرا نمی کند؛ برای مرحله چاپ از آزمون مرورگری نیز استفاده کنید.
5. در صورت عدم تطابق ظاهری یا اختلال در مرورگر، از دکمه روش جایگزین استفاده شود؛ روش قبلی را قبل از قبولی همه تست ها حذف نکنید.

## نکته استقرار

قابلیت های جدید به صورت تغییر محدود Frontend و دو endpoint افزوده شده اند. انجام نشدن آزمون واقعی روی تمام مرورگرها به معنای عدم تضمین یکسانی بصری است.

## اصلاح تجربه پیش نمایش (۹ نوامبر ۲۰۲۶)

- پیش نمایش روش اول اکنون **در همان صفحه پرتال** به صورت پنجره تمام صفحه (dialog) باز می شود؛ دیگر تب جدید یا `window.open` ندارد.
- سند A4 در نمایش موبایل به تناسب عرض صفحه کوچک می شود؛ ابعاد واقعی کاغذ هنگام چاپ ثابت می ماند. جابجایی عمودی، دکمه بستن و کلید Escape پشتیبانی می شوند.
- دکمه «چاپ / ذخیره PDF» بالای پیش نمایش، با کلیک مستقیم کاربر `window.print()` را از سند جاری فراخوانی می کند؛ استایل چاپ فقط فیش را نشان می دهد و ابزارهای پیش نمایش را مخفی می کند. ذخیره PDF به گزینه های چاپ/اشتراک گذاری سیستم عامل وابسته است.
- جمع بندی فیش حقوقی دقیقاً دو ردیف شبکه ای دارد: ردیف اول «جمع مزایا/جمع کسور/جمع اقساط وام» و ردیف دوم «خالص پرداختی/شماره حساب»، با همان نگاشت `FOOTER_LABEL_ROW` در ReportLab. این دو ردیف با هم ادغام نمی شوند و در صورت خالی بودن یک سلول، جای ستون حفظ می شود.
- این اصلاح فقط `frontend/src/services/receiptBrowserPrint.js` را تغییر داده است. مسیر دانلود PDF قدیمی، APIها، مجوزها، سایر ماژول ها و دیتابیس تغییر نکرده اند.
- آزمون عملی روی گوشی های واقعی، iOS Safari و Android TWA هنوز لازم است؛ فراخوانی `window.print()` در بعضی WebViewها ممکن است از طرف میزبان محدود شود. در این حالت دکمه «دانلود PDF (روش جایگزین)» همچنان قابل استفاده است.

## اصلاح سربرگ فیش کارکرد و دانلودمنیجر (۹ نوامبر ۲۰۲۶)

- در پیش‌نمایش چاپ فیش کارکرد، ارتفاع ثابت ۳۷ میلی‌متری سربرگ حذف شد؛ فاصله جدول مطابق جریان معمول عنوان و زیرعنوان، با فاصله ۴ میلی‌متری بعد از سربرگ تعیین می‌شود. لوگو همچنان مطلق در گوشه قرار دارد و ارتفاع اضافی به جدول تحمیل نمی‌کند.
- ضخامت فونت‌های عنوان، زیرعنوان، مقدارها و برچسب‌های فیش کارکرد از Bold مصنوعی مرورگر به Regular تغییر کرد تا به خروجی ReportLab با فونت Tahoma که نسخه Bold جداگانه ندارد نزدیک‌تر باشد؛ اندازه‌های اصلی ۱۵ / ۱۰٫۵ / ۹٫۵ پوینت حفظ شدند.
- در روش جایگزین، دریافت PDF از Backend و کنترل‌های امنیتی تغییر نکرد. استثنای ناشی از تحویل لینک Blob به افزونه دانلودمنیجر دیگر به‌عنوان شکست قطعی دانلود نمایش داده نمی‌شود. در خطاهای فاقد پاسخ HTTP که ممکن است از مداخله دانلودمنیجر باشند، پیام بی‌طرف درباره نامشخص بودن وضعیت نمایش داده می‌شود، نه ادعای شکست قطعی یا موفقیت قطعی. خطاهای واقعی HTTP همچنان گزارش می‌شوند.
- آزمون تجربی با افزونه‌های دانلودمنیجر مختلف، Safari/iOS و چاپ روی موبایل هنوز لازم است. از طرف وب‌اپلیکیشن نمی‌توان مستقل از مرورگر تأیید کرد که دانلودمنیجر فایل را روی دیسک ذخیره کرده است.
- تغییرات محدود به `frontend/src/services/receiptBrowserPrint.js`، `frontend/src/pages/NoticesPage.jsx` و همین مستند هستند.

## اصلاح نوار پیش‌نمایش و خط انتهای جدول حقوق (۹ نوامبر ۲۰۲۶)

- رنگ‌های نوار پیش‌نمایش، عنوان، دکمه اصلی، دکمه بستن و پس‌زمینه مطابق پالت واقعی MUI پرتال در حالت روشن/تیره تنظیم شدند؛ فونت کنترل‌ها وزیرمتن است و ظاهر سند چاپی ثابت مانده است.
- با شناسایی حالت انتخابی `faipco_theme_mode` یا حالت سیستم، رنگ‌های نوار هنگام بازشدن پیش‌نمایش تعیین می‌شوند؛ پیش‌نمایش همچنان در همان صفحه است.
- ردیف‌های اصلی فیش حقوقی در `pay-body` قرار گرفتند تا خط پایین جدول قبل از «جمع مزایا» مستقل از وجود بخش جمع‌بندی رسم شود. منطق فیلدها، جمع‌ها و دو ردیف جمع‌بندی تغییر نکرده است.
- فقط `frontend/src/services/receiptBrowserPrint.js` و همین مستند تغییر کرده‌اند؛ دانلود PDF جایگزین، API، دیتابیس و دیگر ماژول‌ها بدون تغییر مانده‌اند.
- لازم است پیش‌نمایش و چاپ هر دو نوع فیش روی سرور تست در تم روشن/تیره و موبایل بازبینی شوند.

## اصلاح رنگ سند در تم تیره و نوار پیش‌نمایش (۹ نوامبر ۲۰۲۶)

- علت: پیش‌نمایش تمام‌صفحه متن سفید `text.primary` تم تیره را به برگه سفید A4 ارث می‌داد. اکنون برگه با `background: #fff`، `color: #171717` و `color-scheme: light` مستقل از تم است؛ عنوان‌ها و برچسب‌های آبی فیش کارکرد رنگ رسمی چاپ خود را حفظ می‌کنند. همین قواعد در چاپ واقعی نیز اعمال می‌شوند.
- نوار بالایی به الگوی واقعی تم پرتال نزدیک‌تر شد: `background.paper` بدون سایه اضافی (مشابه `MuiAppBar`)، متن `text.primary`، حاشیه `divider`، تایپوگرافی وزیرمتن، دکمه اصلی با `primary.main` و دکمه بستن به شکل Outlined خنثی با گوشه ۶ پیکسل. در موبایل عنوان راست‌چین است و دکمه‌ها عرض مناسب می‌گیرند.
- بر اساس `docs/design-system.md`، `frontend/src/theme.js` و کامنت‌های `ThemeModeContext.jsx` و همین فایل بررسی شد. برگه چاپی عامدانه از رنگ‌بندی تم پیروی نمی‌کند؛ فقط پوسته پیش‌نمایش از آن پیروی می‌کند.
- تغییر کد فقط در `frontend/src/services/receiptBrowserPrint.js` است. مسیر جایگزین ReportLab، Backend، فیش‌ها، دیتابیس و دیگر ماژول‌ها تغییر ندارند.
- آزمون دستی موردنیاز در سرور تست: فیش حقوقی و کارکرد در حالت روشن و تیره، پیش‌نمایش موبایل، و Print / Save PDF در Chrome/Edge/Firefox و Safari/iOS.
