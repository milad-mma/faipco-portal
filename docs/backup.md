# بکاپ پرتال (ZIP + فایل‌های آپلودی + رمز اختیاری)

**تصمیم کاربر (۱۴۰۵/۰۸/۱۱):** بکاپ نسخه‌ی کلیددار (age، نسخه‌های روی سرور، تاریخچه، مجوزهای تفکیک‌شده) بیش از حد پیچیده بود
و کامل حذف شد (Migration 134: حذف مجوزهای backup.* و جدول‌های backup_keys/backup_runs). همان روش قبلی (دانلود ZIP و بازیابی با
آپلود همان ZIP، مجوز `system.backup`) ماند و فقط فایل‌های آپلودی اتوماسیون و «رمز فایل بکاپ» اضافه شد.

## فایل بکاپ
- `faipco-backup-YYYYMMDD-HHMMSS.zip` — اعضا: `database.dump` (pg_dump custom)، `files/objects/...` (فایل‌های اتوماسیون با ارجاع در
  دیتابیس، به‌جز قرنطینه و فایل موقتِ ناموجود)، و در آخر `manifest.json` (حجم و SHA-256 dump و هر فایل، مستثناها، Alembic head).
- **رمز:** اگر در «تنظیمات زمان‌بندی بکاپ ← رمز فایل بکاپ» تعیین شده باشد (حداقل ۸ نویسه؛ `backup_settings.archive_password_encrypted`
  رمزنگاری‌شده با کلید پرتال، Migration 133)، ZIP با AES-256 (WinZip-AES، کتابخانه‌ی `pyzipper`) ساخته می‌شود؛ با 7-Zip/WinRAR و
  همان رمز باز می‌شود (Explorer ویندوز AES را باز نمی‌کند). همه‌ی بکاپ‌ها (دانلود، زمان‌بندی، «اجرا الان») همین رمز را دارند. **تغییر یا برداشتن رمزِ موجود فقط با وارد کردن رمز فعلی**
  (`archive_password_current`، مقایسه‌ی زمان‌ثابت؛ تصمیم کاربر). رمز فراموش‌شده از پنل قابل بازیابی نیست.
- ساخت روی دیسک (`/var/lib/faipco/backups`، موقت) نه در RAM؛ فایل‌ها تکه‌تکه کپی و هش می‌شوند (`services/backup_archive.py`).
- **سازگاری:** تراکنش `REPEATABLE READ READ ONLY` + `pg_export_snapshot()`؛ فهرست فایل‌ها از همان snapshot و `pg_dump --snapshot`
  (آزموده روی PostgreSQL 16). همه‌ی بکاپ‌ها Advisory Lock بکاپ را می‌گیرند؛ پاک‌سازی فایل‌های موقت اتوماسیون همان قفل را می‌گیرد.
- فایل دائم ناموجود یا هش ناهم‌خوان با دیتابیس = بکاپ ناموفق (ناقص ساخته نمی‌شود).

## دانلود و ارسال
- `GET /backup/export` (مجوز `system.backup`): ساخت و تحویل ZIP؛ فایل موقت سرور بعد از تحویل پاک می‌شود.
- زمان‌بندی و `POST /backup/run-now` (پس‌زمینه): ارسال به مقصدهای فعال؛ نتیجه‌ی هر مقصد جدا در «آخرین اجرا»؛ Retention هر
  مقصد (به‌جز ایمیل). فایل موقت بعد از ارسال پاک می‌شود، مگر مقصدی ناموفق باشد (صف تلاش دوباره).

## مقصدها (Migration 135)
| مقصد | پیاده‌سازی | بررسی سالم رسیدن |
|---|---|---|
| پوشه/دیسک محلی | کپی با نام موقت `.name.part`، fsync، تغییر نام | همیشه SHA-256 فایل نوشته‌شده |
| SMB | smbclient (مثل قبل) | حجم با `ls`؛ با «بررسی کامل» دانلود و هش |
| FTP/FTPS | ftplib (مثل قبل) | حجم با `SIZE`؛ با «بررسی کامل» RETR و هش |
| SFTP | paramiko، آپلود با نام موقت و rename | حجم با stat؛ با «بررسی کامل» خواندن و هش |
| S3 و سازگارها | httpx + امضای SigV4 دستی (`core/backup_dest_rules.py`)؛ تک‌تکه تا ۵ گیگابایت | هش بدنه امضا می‌شود و S3 فایل خراب را رد می‌کند؛ بعد HEAD و حجم |
| ایمیل | SMTP (مثل قبل)، ≤ ۲۰ مگابایت | — |

- **پوشه‌ی محلی:** مسیر مطلق، نه داخل مسیرهای سیستمی/پرتال (`check_local_path`)؛ باید برای www-data قابل نوشتن باشد. تست اتصال فضای
  آزاد و هم‌دیسک بودن با `/` را می‌گوید.
- **SFTP:** کلید سرور با «تست اتصال» گرفته و با «ذخیره» ثبت می‌شود (`sftp_host_key`)؛ بعد از آن کلید دیگر = رد اتصال (جلوگیری از
  جعل سرور). تغییر Host/پورت کلید را پاک می‌کند. سرور عوض‌شده: گزینه‌ی «کلید جدید پذیرفته شود» در تست.
- **S3:** Endpoint، Region (پیش‌فرض us-east-1)، Bucket، پوشه، Access/Secret Key (رمزنگاری‌شده)، Path-style (پیش‌فرض روشن). تست
  اتصال یک فایل کوچک می‌نویسد و پاک می‌کند. امضا با نمونه‌های رسمی AWS تست شده است.
- تست: `POST /backup/test-destination/{local|sftp|s3}`.

## صف تلاش دوباره
- مقصد ناموفق (به‌جز خطای دائمی مثل حجم زیاد برای ایمیل) → همان ZIP در `/var/lib/faipco/backups/pending` + فایل JSON (مقصدها، تعداد
  تلاش، زمان بعدی، آخرین خطا). Job `backup_retry_queue` هر ۵ دقیقه زیر قفل بکاپ.
- فاصله‌ها: ۱۵ و ۳۰ دقیقه، ۱، ۲، ۴ و ۸ ساعت (۶ تلاش، حدود ۱۶ ساعت)؛ بعد کنار گذاشته می‌شود. رسیدن بکاپ جدیدتر به یک مقصد، آن مقصد
  را از ورودی‌های قدیمی‌تر حذف می‌کند. حداکثر ۳ فایل در صف (قدیمی‌ترین کنار می‌رود).
- نتیجه‌ی تلاش‌ها در «آخرین اجرا» (بدون تغییر last_run_at که زمان‌بندی به آن وابسته است).
- API: `GET /backup/retry-queue`، `POST /backup/retry-queue/run`، `DELETE /backup/retry-queue/{filename}`.

## بازیابی
- `POST /backup/restore` (فرم: file، confirm=RESTORE، password اختیاری؛ مجوز `system.backup`): فایل تکه‌تکه روی دیسک ذخیره و در
  پس‌زمینه با `stage_zip` باز می‌شود — رمزدار بدون رمز → «رمز لازم است»، رمز اشتباه → «رمز اشتباه است»؛ فقط عضوهای مجاز، سقف حجم و
  تعداد، تطبیق حجم و هش همه‌ی عضوها با manifest، رد بکاپ Migration جدیدتر از کد. فقط اگر سالم بود `schedule_restore(dump, files)`.
- اسکریپت root: توقف سرویس → `objects` فعلی اتوماسیون به `objects.prerestore` و نسخه‌ی بکاپ جایش → schema public کنار → pg_restore →
  alembic → موفق: حذف نسخه‌های قبلی؛ شکست: برگشت دیتابیس و فایل‌ها.
- بکاپ‌های قدیمی (فقط database.dump) هم بازیابی می‌شوند و فایل‌های فعلی دست نمی‌خورند.
- **nginx:** فقط مسیر `/api/v1/backup/restore` بدون سقف حجم و بدون buffer (ZIP بکاپ از سقف آپلود عمومی بزرگ‌تر است).
- وضعیت: `GET /backup/restore-status` (لاگ + `stage`)؛ صفحه نتیجه‌ی آخرین بازیابی را هم نشان می‌دهد. بعد از بازیابی معمولاً ورود دوباره
  لازم است (نشست‌ها به لحظه‌ی بکاپ برمی‌گردند).

## مجوز
- فقط `system.backup` (مثل قبل): دانلود، بازیابی، زمان‌بندی، مقصدها و رمز. پاک‌کردن کش: `system.cache_bust`.

## تست
- `tests/test_backup_destinations.py`: امضای SigV4 با دو نمونه‌ی رسمی AWS، آدرس S3، قواعد مسیر محلی، زمان‌بندی تلاش، آپلود/هش/Retention
  پوشه‌ی محلی، و صف (سقف، حذف با بکاپ جدیدتر، حذف دستی امن).
- `tests/test_backup_zip.py`: قواعد نام/عضو/manifest؛ ساخت ZIP، استخراج و تطبیق هش، فایل ناموجود، هش ناهم‌خوان، عضو جعلی، مسیر
  خطرناک، بکاپ قدیمی؛ رمز (فقط اگر pyzipper نصب باشد — در محیط توسعه نبود؛ روی سرور با requirements نصب می‌شود).

## چک‌لیست سرور تست
1. بعد از آپدیت: alembic 135 (یا بالاتر)؛ `.venv/bin/pip show paramiko`؛ `.venv/bin/pip show pyzipper`؛ در «مدیریت نقش/مجوز» دیگر مجوز backup.* نیست.
2. بدون رمز: «دانلود بکاپ کامل» → ZIP با database.dump، files/ و manifest.json.
3. رمز در تنظیمات → دانلود → ZIP فقط با 7-Zip و همان رمز باز شود.
4. بازیابی همان ZIP بدون رمز → «رمز لازم است» و هیچ تغییری؛ با رمز اشتباه → «رمز اشتباه است»؛ با رمز درست → موفق و فایل‌های
   اتوماسیون قابل دانلود.
5. فایل بزرگ‌تر از ۲۵ مگابایت هم آپلود شود (مسیر بازیابی بدون سقف).
6. پوشه‌ی محلی: `sudo mkdir -p /mnt/backup/faipco && sudo chown www-data:www-data /mnt/backup/faipco` → تست → اجرای فوری → فایل در پوشه.
7. یک مقصد را عمداً خراب کنید (رمز اشتباه) → اجرای فوری → «در صف تلاش دوباره»؛ رمز را درست کنید → «تلاش دوباره همین الان» → صف خالی.
