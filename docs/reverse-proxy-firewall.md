# محدودکردن دسترسی مستقیم به سرور اصلی (پشت پروکسی خارجی)

⚠️ **این یک یافته واقعی از یک تست نفوذ زنده است** — نه یه احتیاط نظری.

## مشکل

اگه یه Reverse Proxy خارجی (برای SSL) جلوی سرور اصلی‌تون دارید، ولی خودِ
سرور اصلی هم مستقیماً (با IP خودش) قابل‌دسترسیه، هرکسی که اون IP رو بدونه
می‌تونه:

1. مستقیم به سرور وصل بشه (نه از طریق دامنه/پروکسی)
2. یه هدر `X-Forwarded-For` جعلی بفرسته (با یه IP داخل رنج مجاز شما)
3. کل قابلیت «رنج‌های IP مجاز» (ضدVPN) رو دور بزنه

این توی این پروژه **تست و تأیید شد**.

## نکته حیاتی: کدوم IP رو مجاز کنم؟

اگه توپولوژی شما **دو لایه‌ست** (پروکسی خارجی روی یه شبکه محلی/خصوصی جدا از
سرور اصلی، مثل اکثر VPS ها) — سرور اصلی **هیچ‌وقت IP عمومی پروکسی رو
نمی‌بینه**. وقتی پروکسی درخواست رو Forward می‌کنه، این اتفاق داخل شبکه
محلی می‌افته؛ سرور اصلی می‌بینه درخواست از **IP محلی پروکسی** اومده، نه IP
عمومی‌ای که دامنه بهش اشاره می‌کنه.

**پس فایروال روی سرور اصلی باید IP محلی پروکسی رو مجاز کنه، نه IP عمومی.**

مثال (فرض کنید سرور اصلی `192.168.99.6` و پروکسی محلی `192.168.99.17` است،
درحالی‌که دامنه به IP عمومی `87.107.138.46` اشاره می‌کند):

```bash
# ❌ اشتباه — سرور اصلی این IP رو هیچ‌وقت به‌عنوان مبدأ نمی‌بینه
sudo ufw allow from 87.107.138.46 to any port 80

# ✅ درست — این IP ایه که سرور اصلی واقعاً می‌بینه
sudo ufw allow from 192.168.99.17 to any port 80
```

اگه مطمئن نیستید کدوم IP درسته، همین الان لاگ Nginx سرور اصلی رو چک کنید
(`$remote_addr` توی لاگ باید IP محلی پروکسی رو نشون بده، نه IP عمومی).

## راه‌حل: محدودکردن Firewall

### روی نصب‌های جدید (توصیه‌شده)

```bash
sudo bash install.sh --reverse-proxy-ip <IP-که-سرور-اصلی-واقعاً-می‌بینه>
```

### روی سرورهای موجود (دستی، همین الان)

```bash
sudo ufw delete allow 80/tcp
sudo ufw delete allow 443/tcp
sudo ufw allow from <IP-محلی-پروکسی> to any port 80
sudo ufw allow from <IP-محلی-پروکسی> to any port 443
sudo ufw status numbered   # تأیید کنید SSH (پورت ۲۲) دست‌نخورده مونده
```

## چطور تأیید کنم درست کار کرده؟

بعد از اعمال، این رو از یه ماشین **دیگه** (نه از پشت پروکسی خارجی، و نه
از خودِ شبکه محلی سرور) امتحان کنید — باید کاملاً Timeout بده یا رد بشه:

```bash
curl -m 5 -X POST http://<IP-مستقیم-سرور>/api/v1/auth/login \
  -H "X-Forwarded-For: 1.2.3.4" \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"test"}'
```

اگه سرور اصلی اصلاً IP عمومی خودش رو نداره (فقط از پشت NAT شبکه محلی
قابل‌دسترسیه)، این تست فقط از **داخل همون شبکه محلی** قابل‌انجامه — که
باز هم بعد از این فیکس باید رد بشه (چون فقط IP خودِ پروکسی مجازه، نه بقیه
دستگاه‌های همون شبکه).

## نکته

این محدودیت فقط پورت‌های ۸۰/۴۴۳ (وب) رو می‌بنده — SSH (پورت ۲۲) دست‌نخورده
می‌مونه.
